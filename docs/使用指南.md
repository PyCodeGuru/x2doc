# 一、这个工具是干什么的

你给它一个 X 链接或微信公众号文章链接。
它会生成 `index.md`、`index.pdf` 和 `assets/` 图片目录。  
完成后，终端会直接告诉你文件保存在哪里。

# 二、只需要做一次的准备

1. 确认 Python 版本。最低要求是 Python 3.11。

```bash
cd /Users/paipai_tm/Work/tools/x2doc && python3 --version
```

成功的样子：看到 `Python 3.11`、`Python 3.12` 或更高版本。

2. 创建 `.venv`，并安装 x2doc。

```bash
cd /Users/paipai_tm/Work/tools/x2doc && python3 -m venv .venv && .venv/bin/python -m pip install -e .
```

成功的样子：最后看到 `Successfully installed x2doc-0.1.0`。

3. 安装 Chromium。

```bash
cd /Users/paipai_tm/Work/tools/x2doc && .venv/bin/python -m playwright install chromium
```

成功的样子：看到 `Chrome for Testing` 已下载，或命令安静结束且没有报错。

4. 确认中文字体。工具支持 `PingFang SC`、`Noto Sans CJK SC`、`Source Han Sans SC`。macOS 自带的 `PingFang SC` 通常已经满足。

```bash
cd /Users/paipai_tm/Work/tools/x2doc && .venv/bin/python -c "from x2doc.renderers.pdf import detect_chinese_font; print('检测到：' + detect_chinese_font())"
```

成功的样子：看到 `检测到：PingFang SC`。

5. 启动 M78、Clash 或 Surge，并确认代理可用。本机实测地址是 `http://127.0.0.1:7892`。

```bash
cd /Users/paipai_tm/Work/tools/x2doc && curl --silent --show-error --proxy 'http://127.0.0.1:7892' --max-time 5 --output /dev/null --write-out 'HTTP %{http_code}\n' 'https://x.com/robots.txt'
```

成功的样子：看到 `HTTP 200`。

6. 跑一次环境自检。11 项全绿后再继续。

```bash
cd /Users/paipai_tm/Work/tools/x2doc && .venv/bin/x2doc doctor --proxy 'http://127.0.0.1:7892'
```

成功的样子：11 行都以 `✅` 开头，最后看到 `✅ 全部通过，可以开始转换。`

7. 可选：给 zsh 增加 alias。以后你在任何目录都能输入 `x2doc`。

```bash
cd /Users/paipai_tm/Work/tools/x2doc && grep -qxF "alias x2doc='/Users/paipai_tm/Work/tools/x2doc/.venv/bin/x2doc'" ~/.zshrc || printf "\nalias x2doc='/Users/paipai_tm/Work/tools/x2doc/.venv/bin/x2doc'\n" >> ~/.zshrc
```

成功的样子：命令没有报错。

```bash
cd /Users/paipai_tm/Work/tools/x2doc && source ~/.zshrc && x2doc --help
```

成功的样子：看到 `doctor` 命令和 x2doc 帮助信息。

# 三、日常使用：三步搞定

1. 在浏览器中打开目标推文或 Article。复制地址栏中的 X 链接。

2. 粘贴链接并运行下面这条命令。这是最常用的命令。它同时生成 Markdown 和 PDF，并把图片保存到本地。

> **最常用命令**

```bash
cd /Users/paipai_tm/Work/tools/x2doc && .venv/bin/x2doc 'https://x.com/ma_zhenyuan/status/2081364662818599028' --proxy 'http://127.0.0.1:7892' --format md,pdf --images local --overwrite
```

把 `https://x.com/ma_zhenyuan/status/2081364662818599028` 换成你的 X 链接。

成功后会看到类似输出：

```text
抓取路径: fxtwitter
MD: output/x/ma_zhenyuan-20260726-代码知识库-从-0-到-1-小白完整教程/index.md
PDF: output/x/ma_zhenyuan-20260726-代码知识库-从-0-到-1-小白完整教程/index.pdf
```

3. 打开输出文件。

输出目录规则是：

```text
output/{平台}/{作者账号或公众号}-{发布日期}-{标题}/
```

真实示例：

```text
output/x/ma_zhenyuan-20260726-代码知识库-从-0-到-1-小白完整教程/
```

打开这个输出目录：

```bash
cd /Users/paipai_tm/Work/tools/x2doc && open 'output/x/ma_zhenyuan-20260726-代码知识库-从-0-到-1-小白完整教程/'
```

把目录名换成终端刚刚显示的输出目录。

直接打开 PDF：

```bash
cd /Users/paipai_tm/Work/tools/x2doc && open 'output/x/ma_zhenyuan-20260726-代码知识库-从-0-到-1-小白完整教程/index.pdf'
```

把 PDF 路径换成终端刚刚显示的 PDF 路径。

你也可以执行交互脚本。它会检查 `.venv`、Chromium 和代理，然后让你粘贴链接。

```bash
cd /Users/paipai_tm/Work/tools/x2doc && ./scripts/x2doc-run.sh
```

成功的样子：脚本最后显示 `MD:` 和 `PDF:` 两条路径。

## 转换微信公众号文章

手机微信里打开文章，点击右上角 `…`，再点击「复制链接」。电脑端可以复制浏览器地址栏。命令和 X 完全一样，微信域名会自动直连，不要求开启代理。

```bash
cd /Users/paipai_tm/Work/tools/x2doc && .venv/bin/x2doc 'https://mp.weixin.qq.com/s/AwOk3di8m6eVeIUjzNftgg' --format md,pdf --images local --overwrite
```

把命令里的微信链接换成你的文章链接。输出位于 `output/wechat/公众号-日期-标题/`。

## 在 iPhone KittyLitter 中转换并上传

你不需要在手机上输入命令。先确认 Mac mini 已开机、KittyLitter 已连接，并且 M78 已启动。

在 KittyLitter 的 Codex 对话中发送下面这句话：

```text
帮我调用 x2doc，把这个链接 https://x.com/yanhua1010/status/2039966047378583815 转成 Markdown 和 PDF，并上传到 GitHub。
```

把句子里的 `https://x.com/yanhua1010/status/2039966047378583815` 换成你的 X 或微信公众号文章链接。

成功后，Codex 会返回四项内容：

- Markdown 路径，例如 `output/x/作者-日期-标题/index.md`
- PDF 路径，例如 `output/x/作者-日期-标题/index.pdf`
- 可在公司电脑打开的 GitHub 目录链接
- 本次 Git 提交哈希

只有返回内容中出现 `status: ok` 和提交哈希，才表示文件已经推送到 GitHub。你可以点击 GitHub 目录链接查看 Markdown，或下载 PDF。

如果手机端返回失败信息，先看其中的 `exit_code` 和 `message`。你也可以在 Mac mini 上运行同一个固定入口复现：

```bash
cd /Users/paipai_tm/Work/tools/x2doc && ./scripts/x2doc-publish.sh 'https://x.com/yanhua1010/status/2039966047378583815'
```

把命令里的 `https://x.com/yanhua1010/status/2039966047378583815` 换成刚才失败的链接。不要自己运行 `git add .` 或拼接其他 Git 发布命令。

# 五、抓长文（Article）和整串（thread）要额外做什么

免登录能抓到大部分公开内容。X 如果返回登录页面，x2doc 会以退出码 2 结束，并提示你使用 `--cookies PATH`。

从 Chrome 导出 cookies：

1. 在 Chrome 打开 `https://x.com`，确认你已经登录。
2. 打开 Chrome 扩展商店，安装 `Cookie-Editor`。
3. 回到 X 页面。点击地址栏右侧的拼图图标。
4. 点击 `Cookie-Editor`。
5. 点击 `Export`。
6. 选择 `JSON`。x2doc 也支持 Netscape 格式。
7. 把下载文件命名为 `x-cookies.json`。
8. 把文件移动到专用目录：

```bash
cd /Users/paipai_tm/Work/tools/x2doc && mkdir -p '/Users/paipai_tm/.config/x2doc' && mv '/Users/paipai_tm/Downloads/x-cookies.json' '/Users/paipai_tm/.config/x2doc/x-cookies.json' && chmod 600 '/Users/paipai_tm/.config/x2doc/x-cookies.json'
```

如果 Chrome 下载的文件名不同，把 `/Users/paipai_tm/Downloads/x-cookies.json` 换成实际下载路径。

带 cookies 运行：

```bash
cd /Users/paipai_tm/Work/tools/x2doc && .venv/bin/x2doc 'https://x.com/ma_zhenyuan/status/2081364662818599028' --proxy 'http://127.0.0.1:7892' --cookies '/Users/paipai_tm/.config/x2doc/x-cookies.json' --thread --format md,pdf --images local --overwrite
```

把命令里的 X 链接换成你的 Article 或 thread 链接。

cookies 等同于账号密码。不要发给别人。不要放进项目目录。不要提交进 Git。项目的 `.gitignore` 已覆盖 `cookies*.json`、`cookies*.txt`、`*.cookies.json`、`*.cookies.txt` 和 `.cookies/`。

# 六、出错了怎么办（对照表）

| 看到的现象 | 退出码 | 原因 | 一句话解决办法 |
|---|---:|---|---|
| 链接既不是 X 也不是微信文章，或没有传链接 | 1 | 参数错误 | 复制完整的 X 推文、X Article 或 `mp.weixin.qq.com/s/...` 链接后重试。 |
| 内容已删除、账号受保护、Article 要登录 | 2 | 当前内容不可访问 | 按第五节导出 cookies，并增加 `--cookies '/Users/paipai_tm/.config/x2doc/x-cookies.json'`。 |
| 微信文章已删除、违规或链接失效 | 2 | 微信不再提供正文 | 换用仍可公开访问的文章链接。 |
| 微信提示环境异常或需要验证 | 3 | 微信临时触发访问验证 | 稍后重试；不要给微信域名配置境外代理。 |
| 源站不可达 | 3 | 通常是代理没启动，或端口已经改变 | 运行下面的代理验证命令。 |
| Chromium 未安装，或中文字体缺失 | 4 | 本地依赖不完整 | 运行 `x2doc doctor`，复制失败项下面的修复命令。 |
| 渲染失败 | 5 | 页面结构变化或文件内容无法解析 | 增加 `--verbose` 重跑，并保留完整输出。 |

验证代理：

```bash
cd /Users/paipai_tm/Work/tools/x2doc && .venv/bin/x2doc doctor --proxy 'http://127.0.0.1:7892'
```

没有退出码，但经常遇到的现象：

| 现象 | 处理办法 |
|---|---|
| 图片没下载下来，Markdown 里只剩远程链接 | 启动代理，然后增加 `--refresh --overwrite` 重跑。 |
| 微信图片返回 403 | 确认使用 `--images local` 重跑；工具会自动携带微信要求的 Referer。 |
| PDF 中文显示方框 | 运行 doctor。确认显示 `PingFang SC`、`Noto Sans CJK SC` 或 `Source Han Sans SC`。 |
| 提示输出目录已经存在 | 增加 `--overwrite`。 |
| 你改了代码，但输出内容没变 | 增加 `--refresh --overwrite`，强制重新抓取。 |

# 七、常见问题

**文件存在哪里？能改位置吗？**

默认在 `/Users/paipai_tm/Work/tools/x2doc/output/`。你可以使用 `--out` 改位置。

X 输出在 `output/x/`，微信输出在 `output/wechat/`。旧版直接放在 `output/` 下的目录可先预览迁移：

```bash
cd /Users/paipai_tm/Work/tools/x2doc && .venv/bin/python scripts/migrate_output.py
```

确认预览后实际迁移：

```bash
cd /Users/paipai_tm/Work/tools/x2doc && .venv/bin/python scripts/migrate_output.py --apply
```

```bash
cd /Users/paipai_tm/Work/tools/x2doc && .venv/bin/x2doc 'https://x.com/ma_zhenyuan/status/2081364662818599028' --proxy 'http://127.0.0.1:7892' --format md,pdf --images local --out '/Users/paipai_tm/Documents/x2doc-output' --overwrite
```

把命令里的 X 链接换成你的链接。

**缓存在哪里？怎么清空？断网还能重新生成吗？**

缓存位于 `/Users/paipai_tm/.cache/x2doc/`。清空前先移到废纸篓，误操作后还能恢复：

```bash
cd /Users/paipai_tm/Work/tools/x2doc && mkdir -p '/Users/paipai_tm/.Trash' && mv '/Users/paipai_tm/.cache/x2doc' "/Users/paipai_tm/.Trash/x2doc-cache-$(date +%Y%m%d-%H%M%S)"
```

这条命令会移动全部 x2doc 缓存。恢复时，把废纸篓里的目录移回 `/Users/paipai_tm/.cache/x2doc`。命中缓存并保留已有 `assets/` 时，断网仍能重新生成 Markdown 和 PDF。

**Markdown 能直接放进 Notion 或 Obsidian 吗？图片会丢吗？**

可以。`--images local` 会把图片放进 `assets/`，移动 Markdown 时要连同 `assets/` 一起移动。`--images embed` 会把图片写进 Markdown，单文件更方便，但文件会变大。

微信远程图片有防盗链，地址可能过期。需要长期保存时使用 `--images local`；需要单个 Markdown 文件时使用 `--images embed`。

**同一个链接跑两次会怎样？**

第二次会命中缓存。输出目录已经存在时，不加 `--overwrite` 会以退出码 1 结束。日常命令可以保留 `--overwrite`。

**能批量处理多个链接吗？**

当前没有单独的批量参数。你可以使用 shell 循环：

```bash
cd /Users/paipai_tm/Work/tools/x2doc && for url in 'https://x.com/ma_zhenyuan/status/2081364662818599028' 'https://x.com/apimctestface/status/1253775785153884161'; do .venv/bin/x2doc "$url" --proxy 'http://127.0.0.1:7892' --format md,pdf --images local --overwrite; done
```

把循环里的两个 X 链接换成你要处理的链接。

**视频和投票能转换吗？**

视频目前最多保留封面或链接，不下载完整视频。投票和第三方嵌入可能只保留文字或链接。

# 八、已知限制

- 受保护账号必须提供有效 cookies，而且你的账号本身要有查看权限。
- X 可能拒绝免登录 Article；此时会提示你提供 cookies。
- 免登录时不能保证找全后续回复。完整 thread 需要 cookies。
- 视频不保证下载正文，通常只保留封面或链接。
- 投票和第三方嵌入可能退化成普通文字或链接。
- X 页面改版后，Article 或 thread 解析可能需要更新。
- `--images none` 不能与 PDF 一起使用。
- 同一输出目录已存在时，需要增加 `--overwrite`。
- 微信环境验证页不会被保存成正文，需要稍后重试。
- 微信音频和视频目前保留占位或封面，不下载媒体正文。
